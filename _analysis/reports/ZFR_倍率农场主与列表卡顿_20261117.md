# 倍率、农场主本地购买与列表卡顿（2026-11-17）

三项改动共用当前 Windows / Android fork，未修改 IPA 和存档格式。用户确认管理器倍率上限扩展到 ×6。初次交付为本地测试版；随后用户已确认 Windows / Android 三项修改全部成功，并授权发布 `v29fix-farmers-scroll`。游戏内成功结论来自用户反馈；局部 guest 测试未测量完整菜单帧耗时。

## 倍率上限

原来 Windows `SettingDefs.window_scale.CustomMax` 与 Android `ZfStorage.scale()` 都限制到 3，底层 `parse_scale_factor` 本来就能接受更高倍率。

- 两端统一支持 1～6 的自定义倍率，继续支持小数和分数。
- Android 预设新增 ×4、×5、×6；新安装默认仍为 iPhone ×3，已有设置保留。
- Windows 保留已有预设，通过“自定义”填写 4、4.5、6 或 9/2。
- iPhone ×6 对应 2880×1920；iPad ×6 对应 6144×4608。提高的是渲染倍率，不改变游戏画布和素材。
- Windows SelfTest 更新上下界、分数、尺寸断言；Android 用 bundled JDK 直接编译执行生产 scale 方法，8 个有效与 9 个无效输入通过。Android instrumentation 同步加入倍率断言，并将历史 IPA 哈希断言更新到当前水印版；本次没有运行设备 instrumentation。

## 农场主购买

原游戏有六个免费形象与九个付费形象。九个购买入口调用 `ZFFarmerSelectionMenu buyHead:`，使用 `com.playforge.ZombieFarm.FarmerHead1`～`9`（iPad 加 `_iPad`）交给旧 StoreKit。停服后该路径无法购买。

新增 `objc/messages/zombie_farm/farmers.rs`，仅作用于 `com.playforge.ZombieFarm.ZFR` / `1.0`：

1. 停止农场主页查询旧商店价格。选中未解锁形象时，按钮显示“15脑子购买”。
2. 点击购买打开游戏自己的 `ZFAlertWindow`，明确询问是否花费 15 脑子永久解锁；可取消。
3. 确认后再次检查当前存档身份及余额，用游戏原 `GameState subResource:amount:` 扣除资源编号 1（脑子）15 个。
4. 仅 OR 对应 `GameData.fflags` 位，保留其它位，调用原形象选择方法，再调用正常 `saveGame` 与脑子显示刷新。
5. 已解锁形象照常选择，不再扣费。取消、余额不足、重复请求/回调和弹窗销毁都有明确处理；弹窗存活期间持有菜单和数据，收尾释放，销毁路径保留 guest 原寄存器。

## 两个列表滑动卡顿

变异列表使用 `CCMultiColumnTableView`，入侵编队使用 `CCTableView`，均依赖相同的 `_evictCell`。iPad 能容下入侵队伍时不触发滚动，符合用户描述的边界。

关键代码证据：`CCTableView _evictCell` 构造 `idx < %i` 与 `idx > %i` 两个 `NSPredicate`，用于筛出可见区间外的格子。旧 `ns_predicate.rs` 只实现了 `idx == ...`，其余回退为 `AlwaysTrue`，结果两次筛选都会把可见格子也选中。随后 `_moveCellOutOfSight:` 删除节点并清空 `node`。另外，旧的 `dequeueCell` workaround 对整个游戏强制返回 nil，使原格子复用也被禁用。滚动时因此反复移除并重建僵尸、标签等内容。

本次：

- Foundation 支持精确 `idx` 的 `= / == / != / < / <= / > / >=` 比较、格式化有符号和无符号整数，以及完整整数字面量。负的有符号边界不会被误读成大无符号数。其它谓词保留原先回退，未声称实现通用 NSPredicate。
- 当前 ZFR 1.0 恢复原 `dequeueCell`，同时放行原 `ZFZombieCell setZombie:`，避免已清空 `node` 的回收格子被旧的“重复赋值跳过”处理误判。其它历史游戏版本保留其既有处理。
- 不改变列表尺寸、偏移、内容、裁剪或游戏选择顺序。

验证包含可见区间保留/边界比较的生产单元测试，以及实际 IPA 的 headless guest 测试：用真实 `CCTableViewCell` 的 `setIdx:` / `idx` 配合生产 `NSMutableArray`、`NSPredicate` 及格式化参数 ABI 处理 28 个格子，`idx < 6` → 6，`idx > 17` → 10，`idx == 12` → 1，负边界分别得到 0 / 28。测试仅加载程序与调用这些局部方法，FS 只读，不运行游戏主循环，不操作玩家数据。该测试没有测量完整菜单的帧耗时。
