# Android 云手机启动崩溃（2026-11-15）

截图中的 `assertion left == right failed / left: 1280 / right: 0` 来自 `src/frameworks/core_animation/composition.rs:369` 的 `assert_eq!(gles.GetError(), 0)`。十进制 1280 即 OpenGL `0x0500 / GL_INVALID_ENUM`。

## 取证与根因

通过用户提供的 ADB 地址连接云手机，确认安装的是上一轮昼夜修复 APK v9。云手机运行 Android 11，底层为 x86_64/ranchu，ARM64 APK 经过 native bridge 执行。图形驱动报告 `OpenGL ES-CM 1.1 (4.6 (Core Profile) / ARM / Mali-G77 MC9`；这只是其报告字符串，不能据此认定底层物理 GPU。

有两个独立问题：

1. touchHLE 的 viewport 缩放判定在新 FBO 尚无附件时就查询 `FRAMEBUFFER_ATTACHMENT_OBJECT_NAME_OES`。OES_framebuffer_object 规定附件类型为 NONE 时，该查询产生 `GL_INVALID_ENUM`。只查询 TYPE，确认是需要判定的 renderbuffer 后再查询 NAME，才能避免这个错误。
2. 云手机 GLES1 转译层对 **renderbuffer 附件的合法 NAME 查询也错误地返回 `GL_INVALID_ENUM`**。先修复问题 1 后，游戏仍崩溃。临时逐调用诊断证明：TYPE 返回 `36161 / GL_RENDERBUFFER_OES`，随后 NAME 查询返回 `0x0500`。独立 x86_64 EGL 探针在全新 FBO 上只挂 renderbuffer，也得到同样结果；纹理附件的同类查询正常。

该 GLES1 编码器还会把错误带到同线程的另一个独立 EGLContext：探针在第一个上下文制造错误、切到第二个上下文后，`glGetError()` 返回 `0x0500`，切回第一个反而返回 0。因此 guest 查询引发的错误最后被 touchHLE 内部合成器读到，触发了截图中的断言。

对照 AOSP Android 11 的 `system/GLESv1_enc/GLEncoder.cpp`：`s_glGetFramebufferAttachmentParameterivOES` 依赖客户端 `attachmentHasObject` 验证；其 override 列表跟踪了 `glFramebufferTexture2DOES`，没有跟踪 `glFramebufferRenderbufferOES`，与独立探针现象一致。云手机本身的代码版本不可确认，结论以设备实测为准。

证据目录：`_analysis/dumps/android-cloud-20261115/`。

- `before-touchHLE-log.txt`：原始崩溃位置。
- `native-probe-x86_64.txt`：空附件、纹理附件、renderbuffer 附件及跨上下文错误的独立实测。
- `diagnostic2-touchHLE-log.txt`：ARM64 游戏内 TYPE/NAME 查询的返回值与错误码；仅诊断包清除了错误，不能当正式修复。
- `after-v10-touchHLE-log.txt`：只修查询顺序的候选仍会崩溃，不能认定为完整修复。

## 修复

- `gles_guest.rs`：缩放判定只在 TYPE 是 renderbuffer 时查询 NAME；trace 查询避开默认 FBO 和无附件对象。
- `gles1_native.rs`：Android 后端从上一轮建立的共享 FBO 附件描述中返回合法 TYPE/NAME 查询，绕过错误的宿主编码器。无附件的 NAME 查询、非法 target/attachment/pname 等仍交给宿主验证；没有全局吞掉 GL 错误。
- `build.gradle.kts`：versionCode 9 → 10。
- 临时逐调用日志及 `GetError()` 诊断全部移除；合成器断言保持原样。

## 应用数据

测试前已保存该云手机当前的外部/内部快照，共 4 个外部文件、2 个内部文件；当时尚无 `saveGame.bin2`。正常启动会初始化玩家资料和偏好两个文件，故测试后须用本轮快照还原，而不是复用 MuMu 或历史存档。

该云手机 `run-as` 无法访问外部 FUSE，应用 UID instrumentation 也无法打开由 root ADB 推入的快照。最终利用该设备已有的 root ADB，在游戏停止后只对两个变化的现有文件原位写回原字节及 mtime，保留 inode、UID `11136`、组 `1078` 和权限 `660`；未解包、未替换文件。4 个外部文件与 2 个内部文件哈希全部匹配。测试 APK 和设备临时探针已移除，游戏已停止。证据为 `root-byte-restore.json`、`restore-result.json`。
