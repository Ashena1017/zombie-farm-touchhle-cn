代码复核：`gles1_native.rs` 的纹理上传、混合、alpha test 大多直接转交宿主 GLES1；Windows 的 `gles1_on_gl2.rs` 使用另一条适配路径。PVRTC 已由两端共用 CPU 解码，不能单凭这台手机不是 PowerVR 就归因于“不支持 PVRTC”。既有 MuMu 抓取中可见 RGBA4444 与 ALPHA 纹理上传，但没有受影响真机的失败调用证据，不能把某个纹理格式直接当作根因。

`eagl.rs` 和 `window.rs` 已在 `touchHLE_log.txt` 写入 `Driver info`；Android 日志位于应用 external files 根目录（常见主用户路径 `/storage/emulated/0/Android/data/org.touchhle.zombiefarm/files/touchHLE_log.txt`），也通过现有 DocumentsProvider 暴露。日志每次进程启动会重建，需保留发生黑框的那次日志，避免重启后覆盖。本次仅复核源码和既有证据、补充记录，没有改渲染代码、重建/安装 APK 或操作存档。

Android 用 native GLES1，Windows 主要使用 GL2 适配层，两者的驱动与纹理格式支持不同，确有设备相关兼容问题的可能。当前仅可列为排查方向，不能从“手机独有”直接确定为渲染器根因。现有夜景 FBO 和云手机附件查询修复已保留，不新增缺乏证据的纹理转换。
