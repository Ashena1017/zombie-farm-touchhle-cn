## 现象与复现

玩家报告 Android 农场始终为白天亮度，Windows 随 touchHLE 模拟时间变化正常。连接 MuMu `127.0.0.1:7555`，先保存外部 sandbox、设置、备份目录及私有偏好/锁文件的原始快照。

只修改管理器的累计时间偏移，不修改 Android 或 Windows 系统时钟。旧 APK 在模拟时间 23:00 时，角色已经提灯，但农场仍亮。F11 Inspector 的 `NSDate` 时间、`DayCycle.currentState=6`、可见 `PointLight` 均证明夜间逻辑生效。

证据均在 `_analysis/dumps/android-daynight-20261115/`：

- `before-23-inspector.txt`、`object-inspector.txt`：模拟时间、夜间状态及渲染节点。
- `before-states.txt`、`before-frames.tar.gz`：第 0～3 次离屏绘制产生有 alpha 的黑色遮罩与灯光轮廓；第 15 次绘制绑定遮罩纹理 21，前后画面像素完全不变。

## 根因

游戏通过共享 EAGLContext 在后台加载线程创建 `CCRenderTexture`。纹理和 renderbuffer 可以由宿主 GLES 共享，但 framebuffer 容器属于宿主上下文本身。此前 touchHLE 直接透传 FBO 名称：主上下文的屏幕 FBO 与后台创建的遮罩 FBO 都是宿主编号 1，后台对象在主上下文中却没有同样的附件。遮罩绘制落到屏幕缓冲并被主场景清除，最终采样的纹理没有得到对应内容。

另有 MuMu GLES1 查询异常：绑定非零 FBO/RBO 后 `glGetIntegerv` 仍可返回 0。独立 native 探针证明 FBO 的实际绘制、采样可用，但查询值不可信。只修查询、记录绑定状态的候选仍不能恢复夜景，不能把它单独写成根因或完整修复。

## 实现

- `src/gles/gles1_native.rs`：Android EAGL sharegroup 共用虚拟 FBO 名称及附件描述；每个宿主上下文保有自己的实际 FBO。绑定时按需创建本地容器，并在附件版本变化时重放纹理/renderbuffer 附件；切换上下文时刷新已绑定对象。生成、查询、删除与未实例化名称的语义同步处理。
- 同文件记录当前 FBO/RBO 绑定值，保证返回的是对应虚拟名称，避免受 MuMu 错误查询及宿主名称差异影响。
- `gles_generic.rs`、`gles1_on_gl2.rs`、`frameworks/opengles/eagl.rs`：Android 创建共享 EAGLContext 时传递对象共享关系。所有新增运行分支限于 Android；桌面 GL2 后端保持既有行为。
- APK versionCode 8 → 9；签名、默认配置、内置 IPA 不变。
- 临时抓帧、状态输出、Inspector 修改全部移除；最终 `gles_guest.rs`、`zombie_farm_debug.rs` 与 HEAD 逐字节相同。

## 存档与权限恢复

原始设备快照是 `before-external.tar` / `before-internal.tar`，没有经过 Windows tar 重打包。最终 **6 个外部文件、2 个私有文件**的路径及 SHA-256 与快照完全一致，累计 offset 恢复为 0，文件 owner 恢复为应用 UID `u0_a64`。确认记录：`restore-result.json`、`restore-owner-result.txt`。

恢复时遇到的实际坑：MuMu toybox tar 从管道解包报 `EOF: Illegal seek`；直接以 adb shell 解包虽然可恢复内容，却把文件 owner 变成 shell，目录 mtime 还原也报权限错误；`run-as` 不能访问该设备的外部 FUSE 路径。最终用 `_restore_android_snapshot_owner.py` + `_android_snapshot_restore.java` 临时 instrumentation，在应用 UID 下重新写回原始快照并恢复时间，逐文件校验后删除测试 APK。原 `ManagerTestRunner.java` 已在 finally 中原字节恢复。**不要再以 shell 身份直接 tar 解包玩家外部存储。**

Windows 开发存档仍为 881 B / SHA-256 `12AFE4B0E81568E7B8EE5FB16F962703A89C28964A2689933DDA1D499EF09DD9`，本轮没有写入。
